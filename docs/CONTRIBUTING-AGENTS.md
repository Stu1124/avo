# Avo — implementation brief for contributors

Native macOS app (AppKit + SwiftUI), Swift language mode 5, no sandbox, deployment floor macOS 15 — guard anything newer. Project generated by xcodegen from `project.yml` (new files under `Avo/` are picked up automatically; run `xcodegen generate` after adding files). Local builds sign ad-hoc and need no Apple Developer account; set `AVO_TEAM_ID` and `AVO_CODE_SIGN_IDENTITY` to sign with your own team, or pass `CODE_SIGNING_ALLOWED=NO` for an unsigned build. See `AGENTS.md` for the three build shapes.

Build (from repo root):
    xcodegen generate >/dev/null && xcodebuild -project Avo.xcodeproj -scheme Avo -configuration Debug -derivedDataPath /tmp/avo-dd build 2>&1 | grep -E 'error:|BUILD'
Never use a derivedDataPath inside ~/Documents.

## What Avo is
A voice agent for the Mac: hold fn → on-device transcript → `AgentRuntime` sends transcript + screen context to the configured provider through `Brain.client()` (`ResponsesClient` for the OpenAI Responses API, `ChatCompletionsClient` for anything OpenAI-compatible) with function tools → tools run locally → results show as cards in the notch → one-line narration. Tool descriptions are the model's routing rules: say what the tool does, when to use it, and what must never be guessed.

## Key types (read these files before writing code)
- `Avo/Agent/Tool.swift`: `protocol Tool` (name, description, params: [ToolParam], confirmation: ConfirmationSpec?, statusLabel, statusIcon, group, run(args, ctx) async -> ToolResult). `ToolResult.ok(json, cards:)` / `.fail(msg, guidance:)`. Acting tools (send/create/update/delete/run) MUST set `confirmation` so the runtime shows the editable card; read tools must not. `ToolContext` carries screenshotPath, selectedText, frontmostApp, clipboard, attachments, transcript.
- `Avo/Cards/CardModels.swift`: `CardKind` cases: confirmation, glance (blocks: header/list/stats/keyValue/bars/progress/badges/text), draft, files, task, reminder, question. Icons are SF symbol names or `"app:<bundle id>"` (e.g. `app:com.apple.MobileSMS`, `app:com.apple.reminders`, `app:com.google.Chrome`).
- `Avo/Notch/NotchController.swift` (`NotchController.shared`): `present(_ card: CardKind, id:)`, `update(id, card)`, `dismissCard(id)`, `status(label, icon:)`, `model.sideTasks` for long-running work, `model.expanded`.
- `Avo/Agent/AgentRuntime.swift`: `AgentRuntime.shared.ask(icon:title:body:options:freeText:) async -> String` shows a question card and waits for the user (voice or click). `AgentRuntime.shared.run(text:)` starts a turn.
- `Avo/Support/Settings.swift`: `Settings.shared` (main actor) for preferences, including the provider style, base URL and model id; secrets via Keychain-backed properties (`apiKey` — the brain provider's key — plus `geminiKey`, `fishKey`, `xaiKey`, `googleClientId`/`googleClientSecret`, `googleRefreshToken`, `googleAccountEmail`).
- `Avo/Agent/Brain.swift` / `Avo/Agent/BrainClient.swift`: provider selection and the streaming client protocol. Add a provider here, not in `AgentRuntime`.
- `Avo/Support/Log.swift`: `Log.info/warn/error`, `Paths.*` (everything under `~/Library/Application Support/Avo/`).
- `Avo/Notch/Theme.swift`: colors, radii, springs, `glassCard()`. Dark glass only. Springs only, never ease-in.
- `Avo/Support/Sounds.swift`: `Sounds.shared.play(.card/.done/.error/...)`.

## Rules
- Own only the files assigned to you. Do not edit files owned by others; if you need a hook in a shared file, add a small extension in your own file instead.
- Every tool: a description that says what it does and when to use it, all params with descriptions, `group` set (e.g. "iMessage", "Reminders", "Finder", "Gmail", "Calendar", "Drive", "Coding", "Text", "Memory", "Spotify", "Apps").
- Never guess data; when a lookup is needed, return a clear error with `guidance` for the model.
- JSON returned to the model must be compact and useful (ids the model needs later, human-readable dates).
- Cards: keep them scannable, ≤6 rows, no walls of text. Use `GlanceCard` with `source`/`sourceIcon` set.
- Keep memory low: no polling loops faster than needed, release resources when idle.
- Build must succeed before you finish. Fix all errors in your files. Report what you implemented and anything you could not verify.

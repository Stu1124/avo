# Working on Avo

Native macOS app: Swift 5 language mode, SwiftUI + AppKit, no sandbox, deployment floor macOS 15.
The Xcode project is generated by xcodegen from `project.yml`, so it is not in the repo — new files
under `Avo/` are picked up automatically the next time you run `xcodegen generate`.

## Commands

- Unit tests: `scripts/test.sh`. It compiles each `tests/*Tests.swift` as a standalone executable
  using the source list on that file's first line (`// deps: Avo/Agent/RequestPolicy.swift …`) and
  runs it. Everything must print PASS.
- Build:
  ```sh
  xcodegen generate >/dev/null && xcodebuild -project Avo.xcodeproj -scheme Avo \
    -configuration Debug -derivedDataPath /tmp/avo-dd CODE_SIGNING_ALLOWED=NO build 2>&1 \
    | grep -E 'error:|BUILD'
  ```
- Install and relaunch: `scripts/install.sh --now`. Without `--now` it builds Release and stops.
- Package a release: `scripts/release.sh` writes a signed, notarized `dist/Avo-<version>.dmg`
  and `.zip`. `--skip-notarize` still signs with Developer ID and only skips Apple's service;
  `--unsigned` is the one that produces an unsigned package, and is what CI falls back to when
  the repo has no signing secrets.
- Check before tagging: `scripts/check-release.sh` greps the tree for personal strings and for
  the old product name, prints every hit, and exits non-zero if there are any.
- Drive the running app: `open "avo://ask?text=what%20time%20is%20it"`, or `scripts/avo ask "…"`.
  Other URLs: `avo://compose`, `avo://settings`, `avo://voice`. Smoke run: `scripts/smoke.sh`.
- **Never put a derivedDataPath inside `~/Documents`.** Use `/tmp/avo-dd*` or `$RUNNER_TEMP`.

## Signing, and the three build shapes

Every signing setting is scoped to the `Avo` target, because an xcodebuild command-line setting is
global to the build and also lands on the SwiftMath package target, which has no team and no
matching identity and then fails to sign. So: `project.yml` reads `AVO_TEAM_ID` from the environment
at `xcodegen generate` time and maps the user-defined `AVO_CODE_SIGN_IDENTITY` that
`scripts/install.sh` forwards onto `CODE_SIGN_IDENTITY`, and `scripts/release.sh` exports
`AVO_RELEASE=true` so xcodegen merges `project-release.yml` (automatic signing plus the hardened
runtime notarization requires). Nothing about signing is passed on an xcodebuild command line.

1. **Ad-hoc** — no variables set. Builds with no Apple Developer account. Every rebuild has a new
   code signature, so the first Keychain read after a rebuild raises an access prompt.
2. **`AVO_TEAM_ID` + `AVO_CODE_SIGN_IDENTITY`** — still the legacy keychain, but a stable identity,
   so stored secrets stay trusted across rebuilds and the prompt stops coming back.
   ```sh
   export AVO_TEAM_ID=XXXXXXXXXX
   export AVO_CODE_SIGN_IDENTITY="Apple Development: you@example.com (XXXXXXXXXX)"
   ```
   Identity names come from `security find-identity -v -p codesigning`.
3. **`AVO_SIGNED=true`**, on top of 2 — merges `project-signed.yml`, which adds the
   data-protection keychain access group `$(AppIdentifierPrefix)app.avo.mac`. That grants access by
   team prefix rather than by binary, so nothing ever prompts. It requires a provisioning profile
   for `app.avo.mac`; without one the build fails to sign. It is deliberately never derived from
   `AVO_TEAM_ID` — a team id is not a profile.

CI builds unsigned with `CODE_SIGNING_ALLOWED=NO`. Release signing in `.github/workflows/release.yml`
uses the repo secrets `AVO_TEAM_ID`, `MAC_CERT_P12`, `MAC_CERT_PASSWORD`, `NOTARY_KEY`,
`NOTARY_KEY_ID`, `NOTARY_ISSUER`; with none of them set the workflow publishes an unsigned zip.

`Avo/Avo.entitlements` is generated by xcodegen (its contents depend on `AVO_SIGNED`) and is
git-ignored, like the `.xcodeproj`.

## Where things live

- Settings: UserDefaults domain `app.avo.mac`. Secrets: Keychain service `app.avo.mac`.
- Data: `~/Library/Application Support/Avo/` — log `avo.log`, `AVO_MEMORY.md`, `mcp.json`,
  `google-oauth.json`, `history.json`, scheduled actions, and `screenshots/`.
- Provider selection: `Avo/Agent/Brain.swift`. Clients: `ResponsesClient` (OpenAI Responses API)
  and `ChatCompletionsClient` (anything OpenAI-compatible), both behind `BrainClient`.
- Tools: `Avo/Tools/*`, protocol in `Avo/Agent/Tool.swift`. Any tool that sends, creates, updates,
  deletes or runs something must set `confirmation` so the runtime shows an editable card.
- Cards and the notch: `Avo/Cards/*`, `Avo/Notch/*`.
- The app mark: `design/` (SVG sources) and `Avo/Notch/AvoMark.swift` (the same geometry as a
  SwiftUI `Shape`). Re-render with `swift scripts/render-icon.swift`.

See [`docs/CONTRIBUTING-AGENTS.md`](docs/CONTRIBUTING-AGENTS.md) for the type-level brief: the
protocols, card kinds and conventions to read before writing code.
